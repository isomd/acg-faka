# Dola 提货接入

## 配置

1. 进入后台的“店铺共享”，新增店铺。
2. 协议选择“Dola 提货”。
3. 店铺地址填写 `https://ops.czai2.ccwu.cc/pickup`。
4. 在“Dola 提货 KEY”中每行填写一个 KEY，也可以直接粘贴完整提货链接。
5. 保存后打开该货源的商品列表，将“Dola账号”接入本地分类。

## 后台管理

后台“交易 → 兑换码管理”现在分为三个页签：

- **用户兑换码**：生成、导入、锁定、解锁和删除发给用户使用的兑换码；可绑定主站本地卡密商品或 Dola 单规格商品。
- **Dola 上游 KEY**：按 KEY 查看实时总数、已提、剩余和提货次数；支持批量添加、验证和安全移除。
- **Dola 提货记录**：查看每个上游提货批次、关联订单、状态和错误；账号明文只在管理员点击单条“查看”时读取，响应禁止缓存。

页面顶部保留商品管理、商品订单、店铺共享和用户提货入口快捷方式。上游 KEY 页签仅站长账号可见，列表只返回掩码；有待恢复批次依赖的 KEY 不能移除。

接入生成的商品默认配置为：

| 起购数量 | 单价 |
| ---: | ---: |
| 1 | 0.95 |
| 100 | 0.80 |
| 150 | 0.75 |
| 1600 | 0.70 |
| 3750 | 0.65 |

单次最大购买数量为 10000。商品接入后仍可在商品管理中调整名称、说明、价格和上下架状态。

## 发货行为

- 库存取所有 KEY 的实时 `remaining` 之和。
- 一枚 KEY 不够时会自动拆到后续 KEY。
- 每次向上游提货最多 200 个，较大订单会自动分批。
- 每个上游批次都会先写入本地提货账本；支付回调重试不会重复提货。
- Dola 用户兑换也使用稳定的幂等请求号；同一个提货请求重试只会读取原账本结果。
- 浏览器网络重试会沿用同一请求号；余额/免费订单即使在上游扣货后本地事务回滚，也会从账本恢复原批次。
- 上游扣货后连接中断时，系统会根据本次请求的专用 User-Agent 从提货历史找回原批次。
- 买家收到的格式为每行一个 `邮箱----密码----cookie`。

## 安全说明

- KEY 不会返回到后台列表或前台接口；编辑货源时留空表示保持原 KEY 不变。
- 不要把带 KEY 的提货链接放入商品说明、工单或公开日志。
- 删除仍有未完成订单所使用的 KEY 会阻止自动恢复；应先处理完相关订单再移除。
